# rgi-catalog

The build and the metadata of an unofficial, cloud-native mirror of the
[Randolph Glacier Inventory](https://rgidata.org) (RGI), published as a
[Portolan](https://www.portolan-sdi.org/) catalog at
<https://source.coop/lqgentner/rgi>.

**This is an unofficial mirror, not endorsed by the RGI Consortium.** The
authoritative source is [RGI 7.0 at NSIDC](https://nsidc.org/data/nsidc-0770/versions/7).
Citation and credit belong to the RGI Consortium:

> RGI 7.0 Consortium, 2023. Randolph Glacier Inventory - A Dataset of Global
> Glacier Outlines, Version 7.0. Boulder, Colorado USA. NSIDC: National Snow
> and Ice Data Center. doi:10.5067/f6jmovy5navz.

The mirror republishes each RGI product as one GeoParquet file and the
outlines as a PMTiles web map archive. The values are those of the RGI
release. [docs/PROVENANCE.md](docs/PROVENANCE.md) lists each fix of a
documented upstream error.

In QGIS, use the
[Portolan Registry plugin](https://github.com/portolan-sdi/portolan-registry-qgis).
**View on map** adds the PMTiles and **Load full data** adds the GeoParquet.

## Kinds of file

| Kind | Where | Example |
|---|---|---|
| Tracked and published | `catalog/`, generated by `render` | STAC JSON, `README.md`, `AGENTS.md`, styles |
| Tracked, never published | outside `catalog/` | `src/`, `metadata/`, `tests/`, `docs/`, this README |
| Neither | git-ignored | `staging/` (GeoParquet, PMTiles), `.cache/` (downloads) |

`catalog/` is generated. Edit `metadata/`, then render. A unit test fails
when `catalog/` differs from a fresh render.

## Build

Run the commands in the [pixi](https://pixi.sh) environment.

```bash
pixi install
pixi run python -m rgi_catalog download --version 7.0   # pinned upstream files into .cache/
pixi run python -m rgi_catalog convert --version 7.0    # GeoParquet files into staging/
pixi run python -m rgi_catalog tiles --version 7.0      # the PMTiles archive into staging/
pixi run python -m rgi_catalog render --version 7.0     # metadata/builds/v7.0.json and catalog/
pixi run check                                          # lint, types, unit tests, catalog gates
```

`render --no-record` renders from the committed build record and needs no
staged files.

| Path | What it is |
|---|---|
| `metadata/catalog.yaml` | Titles, prose, providers, citations, links, versions |
| `metadata/columns.yaml`, `codes.yaml` | Descriptions of all columns and of the coded values |
| `metadata/sources.yaml` | The upstream files, pinned by URL, sha256 and size |
| `metadata/builds/v7.0.json` | Sizes, checksums, extents and schemas, written by the build |
| `metadata/templates/` | The README and AGENTS templates |
| `src/rgi_catalog/` | The build |
| `docs/DESIGN.md` | Measured decisions: writer settings, row groups, tiles, styles |

## Publish

Upload the data first, then the catalog documents. Both scripts are dry runs
without `--confirm`.

```bash
pixi run python tools/upload_data.py             # staging/ to s3://lqgentner/rgi
pixi run python tools/upload_data.py --confirm
pixi run python tools/publish.py                 # catalog/ to s3://lqgentner/rgi
pixi run python tools/publish.py --confirm
```

Both scripts only add and replace objects. Never use `portolan push`.

## Gates

| Gate | What it checks |
|---|---|
| `tests/unit/` | The build, the render, and that `catalog/` matches a fresh render |
| `tests/test_links.py` | Every relative link and asset href resolves |
| `tests/test_publish.py` | Nothing outside `catalog/` can be uploaded |
| `tests/test_upload_data.py` | Only staged files with an allowed suffix upload |
| `tests/test_stac_valid.py` | Valid STAC 1.1.0, via `stac-check` |
| `tests/test_conformance.py` | Portolan conformance, via `rashid` |
